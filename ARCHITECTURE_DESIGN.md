# Архитектура поддержки альтернативных путей получения технологий

## Проблема
Текущая архитектура JSON файла не позволяет описать получение одной технологии разными путями.

**Пример:** Водород можно получить:
1. Через электролиз воды
2. Через паровую конверсию метана

В текущей структуре `условия` - это список технологий, которые должны быть выполнены ВСЕ (логика AND).
Нужна возможность описать альтернативные пути (логика OR).

## Текущая структура
```json
{
  "технологии": [
    {
      "название": "Технология",
      "описание": "Описание",
      "условия": ["Условие1", "Условие2"]  // AND: нужны И Условие1, И Условие2
    }
  ]
}
```

## Предложенное решение

### Вариант 1: Расширенная JSON структура с альтернативными путями

```json
{
  "технологии": [
    {
      "название": "Водород",
      "описание": "Химический элемент",
      "условия": [
        ["Электролиз", "Вода"],           // Путь 1: электролиз воды
        ["Паровая конверсия", "Метан"]    // Путь 2: паровая конверсия метана
      ]
    }
  ]
}
```

**Логика:**
- Внешний массив `условия` содержит альтернативные пути (OR)
- Каждый внутренний массив - это набор технологий для одного пути (AND)
- Технология доступна, если выполнен ХОТЯ БЫ ОДИН путь полностью

### Вариант 2: Явное указание логики

```json
{
  "технологии": [
    {
      "название": "Водород",
      "описание": "Химический элемент",
      "пути_получения": [
        {
          "название": "Электролиз воды",
          "условия": ["Электролиз", "Вода"]
        },
        {
          "название": "Паровая конверсия метана",
          "условия": ["Паровая конверсия", "Метан"]
        }
      ]
    }
  ]
}
```

### Вариант 3: Обратная совместимость

```json
{
  "технологии": [
    {
      "название": "Простая технология",
      "описание": "Старый формат",
      "условия": ["Условие1", "Условие2"]  // Старый формат (AND)
    },
    {
      "название": "Водород",
      "описание": "Новый формат с альтернативами",
      "условия": [
        ["Электролиз", "Вода"],
        ["Паровая конверсия", "Метан"]
      ]
    }
  ]
}
```

**Логика обратной совместимости:**
- Если `условия` содержит строки → старый формат (AND логика)
- Если `условия` содержит массивы → новый формат (OR логика между путями)

## Рекомендация

**Вариант 3** - наилучший выбор, так как:
1. ✅ Обратная совместимость с существующими данными
2. ✅ Простота структуры
3. ✅ Легко определить тип по структуре данных
4. ✅ Не требует миграции существующих 300+ технологий
5. ✅ JSON остается читаемым

## Изменения в коде

### 1. Функция проверки доступности технологии

```python
def is_tech_available(tech_name):
    for tech in data['технологии']:
        if tech['название'] == tech_name:
            conditions = tech['условия']

            # Проверка формата условий
            if not conditions:
                return True

            # Проверка типа первого элемента
            if isinstance(conditions[0], str):
                # Старый формат: все условия должны быть выполнены (AND)
                for parent in conditions:
                    if not tech_flags.get(parent, False):
                        return False
                return True
            elif isinstance(conditions[0], list):
                # Новый формат: хотя бы один путь должен быть выполнен (OR)
                for path in conditions:
                    path_completed = True
                    for parent in path:
                        if not tech_flags.get(parent, False):
                            path_completed = False
                            break
                    if path_completed:
                        return True
                return False

    return True
```

### 3. Редактор

Редактор должен поддерживать:
- Добавление альтернативных путей
- Редактирование каждого пути отдельно
- Визуальное отображение путей

## Преимущества решения

1. **Гибкость**: поддержка как простых, так и сложных деревьев зависимостей
2. **Обратная совместимость**: существующие данные работают без изменений
3. **Расширяемость**: легко добавлять новые пути
4. **Простота**: структура остается понятной и читаемой
5. **JSON формат**: не требуется переход на SQLite

## Недостатки SQLite альтернативы

SQLite был бы избыточен для этой задачи:
- Сложнее редактировать вручную
- Требует больше кода для работы
- Менее портативен (бинарный формат)
- Избыточен для дерева из ~300 технологий

JSON с предложенной структурой полностью решает задачу.
