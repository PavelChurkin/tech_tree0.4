# Руководство по использованию альтернативных путей в технологическом древе

## Описание решения

Реализована поддержка описания получения одной технологии разными путями в JSON формате.

**Пример из задачи:** Водород можно получить либо через электролиз воды, либо через паровую конверсию метана.

## Формат данных

### Старый формат (обратная совместимость)

Все существующие JSON файлы продолжают работать без изменений:

```json
{
  "название": "Технология",
  "описание": "Требует ВСЕ условия",
  "условия": ["Условие1", "Условие2", "Условие3"]
}
```

**Логика:** Технология доступна, если выполнены **ВСЕ** условия (AND логика).

### Новый формат (альтернативные пути)

Для технологий с несколькими путями получения:

```json
{
  "название": "Водород",
  "описание": "Может быть получен разными способами",
  "условия": [
    ["Электролиз", "Вода"],
    ["Паровая конверсия", "Метан", "Катализатор"]
  ]
}
```

**Логика:**
- Внешний массив содержит альтернативные пути (OR логика)
- Каждый внутренний массив - набор технологий для одного пути (AND логика)
- Технология доступна, если выполнен **ХОТЯ БЫ ОДИН** путь **ПОЛНОСТЬЮ**

## Примеры использования

### Пример 1: Водород (как в issue #2)

```json
{
  "название": "Водород",
  "описание": "H₂ - может быть получен двумя способами",
  "условия": [
    ["Электролиз", "Вода"],
    ["Паровая конверсия", "Метан", "Катализатор"]
  ]
}
```

Водород будет доступен если:
- Изучены "Электролиз" **И** "Вода", **ИЛИ**
- Изучены "Паровая конверсия" **И** "Метан" **И** "Катализатор"

### Пример 2: Металл из разных руд

```json
{
  "название": "Железо",
  "описание": "Может быть получено из разных руд",
  "условия": [
    ["Печь", "Магнетит"],
    ["Печь", "Гематит"],
    ["Печь", "Сидерит"]
  ]
}
```

Железо будет доступно если изучена "Печь" И хотя бы одна из руд.

### Пример 3: Энергия из разных источников

```json
{
  "название": "Электростанция",
  "описание": "Может работать на разном топливе",
  "условия": [
    ["Турбина", "Уголь"],
    ["Турбина", "Природный газ"],
    ["Солнечные панели"],
    ["Ветряная турбина"]
  ]
}
```

Электростанция доступна через любой из четырёх путей.

### Пример 4: Комбинация форматов

```json
{
  "технологии": [
    {
      "название": "Простая технология",
      "описание": "Старый формат",
      "условия": ["Родитель1", "Родитель2"]
    },
    {
      "название": "Сложная технология",
      "описание": "Новый формат",
      "условия": [
        ["Путь1Шаг1", "Путь1Шаг2"],
        ["Путь2Шаг1", "Путь2Шаг2", "Путь2Шаг3"]
      ]
    }
  ]
}
```

Оба формата могут использоваться в одном JSON файле.

## Как определить, какой формат использовать?

1. **Используйте старый формат**, если технология требует выполнения всех условий одновременно:
   ```json
   "условия": ["Условие1", "Условие2"]
   ```

2. **Используйте новый формат**, если технологию можно получить разными способами:
   ```json
   "условия": [
     ["Способ1Условие1", "Способ1Условие2"],
     ["Способ2Условие1"]
   ]
   ```

## Визуализация

В графе технологического древа:
- Все родители из всех путей будут отображены
- Рёбра будут проведены от всех родителей к технологии
- Цвет узла технологии будет:
  - 🟢 **Зелёный**: технология изучена
  - 🟡 **Жёлтый**: технология доступна (хотя бы один путь выполнен)
  - 🔴 **Красный**: технология недоступна (все пути неполны)

## Технические детали

### Автоматическое определение формата

Код автоматически определяет формат условий по типу первого элемента:

```python
if isinstance(conditions[0], str):
    # Старый формат: список строк
    # Логика: AND между всеми элементами
elif isinstance(conditions[0], list):
    # Новый формат: список путей
    # Логика: OR между путями, AND внутри каждого пути
```

### Функции поддержки

- `is_tech_available(tech_name)` - проверяет доступность технологии
- `is_parent_in_conditions(parent_name, conditions)` - проверяет наличие родителя в условиях
- `find_all_parents(tech_name)` - находит всех родителей для визуализации

Все функции поддерживают оба формата.

## Вопросы и ответы

**Q: Нужно ли переделывать существующий файл techno2.json?**

A: Нет! Он продолжит работать без изменений.

**Q: Можно ли использовать одиночный элемент в новом формате?**

A: Да, но это не имеет смысла. Для одного условия используйте старый формат: `["Условие"]`, а не `[["Условие"]]`.

**Q: Как добавить новый путь к существующей технологии?**

A: Откройте редактор, найдите технологию и измените формат условий со списка строк на список путей.

**Q: Работает ли это в редакторе?**

A: Да! Редактор позволяет добавлять условия. Для создания альтернативных путей отредактируйте JSON напрямую или измените структуру вручную.

**Q: Почему не использовали SQLite?**

A: SQLite избыточен для этой задачи. JSON проще редактировать, он более портативный и читаемый, а для 300+ технологий производительности JSON достаточно.
